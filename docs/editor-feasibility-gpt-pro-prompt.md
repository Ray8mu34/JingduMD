# 交给 GPT Pro 的静读编辑功能评审提示词

请结合我附上的《静读 Markdown 编辑功能实现难度调研》，独立评估是否值得为我的桌面 Markdown 阅读器加入编辑功能。先评估难度和长期维护，不要直接给实施方案，也不要默认劝我继续开发。

我的场景是：从空白开始写较长的中文学习记录，混合公式、代码、截图和列表，也会修改旧笔记。笔记分散在不同阶段和项目目录，不希望重新组织成统一知识库。我喜欢静读现在的阅读排版，但如果自研编辑器成本很重，愿意直接使用 Obsidian。

目标是 Ob 基础编辑体验加部分输入增强的组合，增强功能内置在产品中。我不想开发 Ob 插件，不需要插件市场，也不要求兼容加载 Ob 插件。请不要把“无需插件系统”误判为“输入增强容易实现”。

讨论中的三种模式：

- 阅读：保留现有静读的排版与操作完全一致。
- 编辑：对标 Ob Live Preview，日常可以一直在此写作；光标进入格式内容时显示必要语法。
- 源码：完整 Markdown，用于精确修改；编辑和源码应共享内容、撤销历史和文档会话。

已有文件默认阅读；新建笔记进入编辑是目前提出的方案。图片粘贴/拖放、中文输入稳定、可靠撤销和保存是实际写作需求。公式增强要区分命令候选、固定 snippet/Tab 占位符，以及自动分数、矩阵和复杂规则三种深度。直接编辑表格和复杂图片操作也请单独估算。

静读当前为 Tauri 2 + Rust + React 18 + TypeScript。阅读器使用 ReactMarkdown、remark/rehype、KaTeX、Mermaid、highlight.js 和自定义语法。没有现成编辑内核。已有多标签、多窗口、文件监听、本地图片读取、阅读位置和文件内彩色高亮。

源码仓库：[Ray8mu34/JingduMD](https://github.com/Ray8mu34/JingduMD)。请优先核查[开发分支 codex/reading-reliability-typography](https://github.com/Ray8mu34/JingduMD/tree/codex/reading-reliability-typography)。2026 年 10 月 14 日核对时，主分支为 0.9.1，开发分支为 0.9.3（提交 `8fde994`），报告依据的本地工作目录为 0.9.5，存在尚未上传的图片、高亮等改动。以报告描述为当前状态，远端源码用于辅助核查；具体差异应先标明版本，不要混作同一份源码。

当前源码的三个关键约束：

1. ReaderWorkspace 用 App key={active} 渲染当前标签，切标签会重建页面。草稿与撤销栈不能只放在页面组件内。
2. external-change 会直接重载当前文件，新增编辑后不能覆盖未保存稿。
3. write_file_highlights 只允许修改高亮标记，不能修改正文；需要新通用保存能力并保留旧接口约束。已有备份与磁盘校验可以借鉴，但不等于自动保存和冲突处理已经完成。

还要处理阅读显示未保存稿时执行高亮的写入与撤销一致性；原始 Markdown 与阅读时公式/高亮预处理的分离；UTF-8/UTF-16/GBK 和换行策略；本地截图保存、相对路径、多窗口和外部编辑冲突。

研究线索及限制：

- CodeMirror 6 装饰层符合保留源码、隐藏标记的方向，但实时预览扩展需要维护。
- ink-mde 有混合 Markdown、文件输入回调和 KaTeX 插件，扩展 API 文档标为 experimental。
- codemirror-live-markdown 仓库 main 的 package.json 为 0.5.2-alpha.1；功能列表不构成稳定性证明。
- Silkdown 声称提供 Ob 风格预览，但此次仓库历史很有限，不能预设成熟。
- Vditor 有即时渲染等模式，需评估 Markdown 往返保真、Lute 语义差异、本地附件适配和离线资源。
- Milkdown 基于 ProseMirror/remark，须评估源码保真与本需求交互的匹配。
- LaTeX Suite 的 CodeMirror 移植 Snippetleaf 明确只支持 LaTeX 文档，不能假定直接适配 Markdown 中的局部公式。
- Easy Typing、Paste Image Rename、Advanced Tables、Editing Toolbar 作为操作参考，不要求全量复制它们。

重要的新前提：Obsidian 1.14 桌面公开版已支持打开 vault 外的 Markdown，并按文件目录解析本地图片和链接。仍需要确认所需插件和新附件插入在外部文件中的工作流。[官方发布说明](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/)

2. 明确能力边界和技术路线对比，区分内核已提供、自研集成、特殊语法与宿主状态管理。

6. 比较继续自研、仅辅助编辑、Ob 写作加静读阅读、直接使用 Ob，给出适用条件和停止自研的判断标准。
