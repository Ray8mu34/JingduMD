# 静读 Markdown 0.8.0 阅读与 UI 实机评审

评审日期：2026-09-25。

## 范围与方法

实际启动并操作安装在 `C:\Program Files\JingReader\jingreader.exe` 的软件，文件版本与产品版本均为 **0.8.0**。通过文件列表打开 fixtures 内的文档，观察正文、公式、代码、表格、大纲及设置面板，并进行滚动、章节跳转和窗口缩窄对比。不是仅依据源码进行推测。

实机查看了以下六份文件的代表性区域，并非逐行验收：

- `reader-showcase.md`：中西文混排、Callout、公式、短代码、表格、大纲。
- `typography-proof.md`：H1–H6、长标题、列表公式、单行代码、长代码和九列表格。
- `anonymous-timeline.md`：七列表格、窄窗口和侧栏占位。
- `chinese-longform.md`：中文连续阅读、深层标题与阅读位置恢复。
- `第03章_层级视觉Transformer.md`：技术术语、行内公式、展示公式、章节导航。
- `第04章_自监督学习.md`：学术长段落与连续公式。

主要观察条件为现有用户设置下的“阅读／暖纸”、18 px、标准行距与标准栏宽；详细设置显示行距 1.85、栏宽 760 px、段距 0.88 em、正文左对齐。这是本次运行时的设置，不代表全新安装的默认设置。观察窗口约为 1383 × 903，以及缩窄后的约 933 × 903；尺寸按工具截图计。

未完成所有外观、所有 fixture、英文长文专门测试、完整图片查看器、Mermaid、搜索、高亮、打印及多屏 DPI 回归，因此不对这些能力作通过或失败结论。本次未修改软件代码或测试原文。

## 总体判断

0.8 已有比较统一、安静的阅读外观。正文没有被大量卡片装饰打断，普通公式与解释文字衔接自然，Callout、代码、表格也有可识别的样式。下一步应优先改善**窄窗空间分配、表格列宽和辅助界面的辨认度**，再精修标题与短内容的排版节奏。

下文的“高／中／低”为阅读体验改进顺序，并非崩溃或数据风险级别。视觉判断未做仪器化对比度测量。

## 优先改进清单

### 1. 高：窄窗口仍同时保留两侧栏，正文宽度不足

**实机现象**：约 933 px 宽时，文件树仍约占 270 px，大纲约占 230 px，正文滚动区只剩约 430 px，实际文本更窄。时间轴和中文段落的换行明显增多。手动收起大纲后，内容宽度立即改善。

**影响**：两侧辅助导航合计比阅读区域还宽，尤其不利于并排阅读和技术文档。

**建议**：根据剩余正文宽度决定侧栏形式，而不仅根据总窗口宽度切换。正文空间不足时先将大纲改为浮层，必要时再将文件树改为抽屉；提供明显的一键专注阅读入口，并记住用户选择。

**验收方向**：在约 900–1100 px 窗口及侧栏不同组合下，避免默认保留过窄正文；开关侧栏后保持当前阅读段落。源码辅助核对显示当前窄窗判定为 `window.innerWidth < 900`，与本次临界宽度现象一致。

### 2. 高：表格为了适配宽度，把文字列压缩得过窄

**实机现象**：`anonymous-timeline.md` 在窄窗双侧栏下，“背景与决定”“过程记录”等列出现每行约两三个汉字的排法，短说明被拉成长条，单行记录高度明显膨胀。日期 `2024-01` 在较宽窗口也拆成两行。`typography-proof.md` 的“最后一列”等短表头亦发生不理想换行。

**影响**：表格虽然没有撑破窗口，也有横向位置控件，但跨行、跨列比较仍很吃力。

**建议**：按内容类型分配列宽；日期、状态、编号等短字段尽量不拆，长说明列设置合理最小宽度，超过可用宽度后再横向滚动。保留现有横向位置控制；长文字单元格宜顶端对齐，减少同一行中各列起点错落。

**验收方向**：同一条时间轴记录不因视口变窄而成为多列“竖条”；最右列仍可到达，日期不被无意义拆开。不要为了完全消除横向滚动而牺牲阅读效率。

### 3. 高：大纲与辅助标签的可读性弱于正文

**实机现象**：正文 18 px 较易阅读，但大纲未选中项、文档标题栏、代码语言和行数、设置中的小标签显得偏小、偏淡。暖纸底色下，细笔画中文尤其不易快速辨认。大纲当前项加粗后才明显突出。

**影响**：用户需要从阅读状态切换到“仔细辨认控件”，导航成本较高。

**建议**：为 UI 单独定义字号、字重和对比度，不让正文风格主导控件的可读性；大纲可试用 14–15 px，普通条目提高对比度，当前项通过背景或侧边标记强调。主要操作文字不应仅以浅灰弱化。

**验收方向**：在真实 Windows 缩放设置下复核常用控件；正文与 UI 分别调整字号。这里是实机视觉判断，不是已经测得对比度不达标。

### 4. 中：中西文标题的视觉字重不均衡

**实机现象**：`typography-proof.md` 的 “2026”“English Notes”“Mixed Heading”，以及学术文档中的 “Transformer”“backbone”，比同一标题中的中文更黑、更醒目。

**影响**：视觉重点容易落到年份和英文片段，而非标题整体；长标题中尤其明显。

**建议**：按中西文字体组合校准标题字重、字面大小和基线，避免简单共用同一粗体值。用现有混排校样建立成组的视觉校验；允许保留书页风格，但控制两种文字的灰度差。

### 5. 中：H5、H6 与普通正文的区分较弱

**实机现象**：混排校样的五、六级标题与中文长文的“第五层”“第六层”，字号接近正文，标题之间主要依赖少量字重和间距差异；大纲里的深层条目又不断缩进，留给标题的宽度更少。

**建议**：为深层标题制定稳定的字重与上下间距，确保“上方分节、下方承接”的关系；限制深层大纲缩进的总量。可提供大纲层级筛选或折叠，以减少长文扫描负担。

**验收方向**：即便不看目录，也能识别 H5/H6 为章节入口；无需靠继续增大字号或增加装饰线来区分。

### 6. 中：单行代码块的外壳偏重

**实机现象**：`typography-proof.md` 中只有 `x = 1` 的代码块仍占约百像素高度；语言／行数栏和上下留白占了相当大比例。综合样例中的单行无语言代码也类似。

**影响**：短示例把连续论述切成较大的空段，技术文档滚动量增加。

**建议**：对 1–3 行短代码使用较紧凑的垂直留白，将语言、行数和操作放入紧凑工具栏；较长代码继续保留现有容器。折叠等操作应有清晰的悬停与键盘焦点状态。

### 7. 中：阅读设置占住正文，预览不够方便

**实机现象**：右上角设置弹层向左覆盖文章右侧并遮住大纲；进入“段落与细节”后覆盖范围更大。用户调整参数时，完整的一行文字和部分标题会被挡住。

**建议**：宽窗可以采用设置侧栏并为正文保留完整预览区；窄窗提供小型混排预览。让字号、行距、栏宽的作用能在不关闭面板的情况下判断。

### 8. 中：设置里的模式关系和参数含义还可以更直观

**实机现象**：快速设置中有“阅读／研读”“紧凑／标准／舒展”；详细面板则出现 1.85、760 px、0.88 em 等值，以及“个人排版”“兼容样式”。仅从界面文字不容易预判模式切换会改变哪些参数。

**建议**：给模式配一句简短用途说明或小样张；栏宽同时显示“约每行多少字”；段距等参数提供直观解释。切换预设、恢复默认前应明确作用范围，应用后提供轻量撤销。

### 9. 中：长文件名缺少更易扫描的展示方式

**实机现象**：左侧 `第03章_层级视觉Transformer.md` 被省略，固定文件树宽度又不足以显示完整名称。学术文档可能共享较长前缀，末尾主题被截断后较难区分。

**建议**：支持文件树宽度调整；允许显示文档标题作为主行、文件名作为次行，或提供两行显示选项。完整路径提示可以保留，但不应成为区分文件的主要方法。

### 10. 低：进度和位置恢复的反馈可以更明确

**实机现象**：已有阅读位置恢复；部分样例打开时直接出现在中后部。顶部细进度线较克制，但仅凭它难以判断已经读到何处，也不明显说明“已恢复上次位置”。

**建议**：恢复时短暂显示“已回到上次阅读位置 · 返回文首”；提供可选的百分比或当前章节信息。持续显示可以很轻，避免挤占顶部工具栏。

### 11. 低：空白页的主要动作没有跟随当前状态变化

**实机现象**：启动时文件列表已经展开、fixtures 文件可见，但中央空白页仍以“打开文件列表”为主要按钮。

**建议**：文件树已展开时改为更符合状态的提示，例如“从左侧选择文档”，或提供“继续上次阅读”；只在文件树隐藏时显示“打开文件列表”。

## 不应直接归为软件缺陷的现象

1. **综合样例中的 20 列表格以原始文本显示**：读取源文件核对后，表头为 20 列，分隔行为 19 列。这是样例语法不匹配，应先修正 fixture 再验证宽表渲染；本次未改动它。
2. **章节跳转位置的一次偏差**：第一次进入 Transformer 章节并点击 3.2 后，观察到该节后部位于视口上方；随后点击 3.3 则可正常将标题置于顶部。可能涉及异步内容高度变化或滚动过程，尚不足以断言稳定缺陷。建议针对首次打开、公式尚未完成布局时反复跳转做专项复测。
3. **图片区的一次空白画面**：综合样例的图片区在滚动过程中曾只出现操作按钮与空白，未完成静止状态及图片查看器复核，不列为确认的图片加载故障。
4. **样式偏好不等于功能故障**：中文正文采用书页式风格本身合理；上述字重、标题层次和代码密度建议应保留为可比较的设计方案，而非宣称所有用户都需要更紧凑或无衬线排版。

## 建议实施顺序

第一批处理窄窗侧栏、表格最小列宽和 UI 小字。这三项直接改善内容的可读空间与操作辨认度。

第二批统一中西文标题字重、深层标题节奏、短代码块密度，并改善设置预览。

第三批完善文件列表、进度恢复、空白状态与设置文案，同时补做首次章节跳转和图片加载的专项验证。

已经表现较好的正文连续性、公式与解释的衔接、轻量引用样式、宽内容局部横向滚动机制应继续保留。优化重点是减少阅读阻力，而不是增加装饰。
